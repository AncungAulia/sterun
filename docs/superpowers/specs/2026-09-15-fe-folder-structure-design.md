# `fe/` folder structure: grouped by feature

Date: 2026-09-15. Asked for by Ancung after STE-21 round 1 merged (PR #46). No ticket, by her call.

## Why

`fe/` had grown by layer, not by feature:

- `test/` held 93 test files in one flat folder.
- `modules/organiser/component/` held 31 components for three different pages (the dashboard, the
  create wizard, one race's console).
- `hooks/` (21) and `lib/` (22) were flat, mixing what every page needs (the wallet, the API
  client) with what one feature needs (`useEntryAttempt`, `entry-store`, `run-progress`).
- The rules in `guides/ARCHITECTURE.md` were broken in places and the guide itself was stale:
  `entry` imported from `event-detail/component/` and `organiser/missing`, three hooks imported
  from `modules/`, `WalletButton` imported from `modules/entry/component/`, and a component lived
  in `app/`.

A count before deciding (a script over every import): **no source file and no test is unused**.
The feeling of "too many files" comes from where they sit, not from dead code. About eight
exported functions and constants are only used inside their own file.

## The rule

A file used by one feature lives in that feature's folder. A file used by two or more moves up to
a shared folder, grouped by what it is for.

Two exceptions, both deliberate:

- `hooks/useChainWrite.ts` stays shared with one user today, because the scanner (STE-22) writes
  to the chain through it next.
- `components/ui/` is shadcn's, and stays whole whoever uses each part.

A module may import another module's **page component** (the wizard's Review step renders
`event-detail/EventView`, the public race page), never anything under its `components/`, `hooks/`
or `lib/`.

Inside any folder: the page components at its root, then `components/`, `hooks/`, `lib/`, and
`__tests__/` for the tests of the files beside it. Module subfolders are `components/` (plural),
matching the shared one.

## Tests

A test lives in `__tests__/` in the folder of the file it tests, so it is found next to its code
and the component list stays readable. `test/` keeps only what belongs to no one feature:
`setup.ts`, `e2e/`, `ui-rules.test.ts`, `env-file.test.ts`, `console-chrome.test.tsx` (the route
layouts) and `providers.test.tsx` (`app/providers.tsx`). The directory fixtures move to
`modules/directory/__tests__/fixtures.ts`.

`vitest.config.ts` includes `src/**/__tests__/**`. `ui-rules.test.ts` skips `__tests__`: its
sweeps are about text a user reads, and a test's strings are not that (some are banned dashes on
purpose).

## Merged, extracted, trimmed

- `hooks/use-mobile.ts` into `hooks/useMediaQuery.ts`: `useIsMobile` is `useMediaQuery` with the
  phone breakpoint.
- `NotAllowedNotice` and `NotAllowlisted` into one `NotAllowed.tsx`: the same message as a note in
  the console and as the wizard's full screen.
- `joinAddOns` out of `event-detail/component/TabAddOns.tsx` into `lib/event/add-ons.ts`, because
  `entry` needs it; `focusField` and the `Missing` type out of `organiser/missing.ts` into
  `utils/missing-field.ts`, same reason.
- `export` dropped from functions and constants only their own file uses. Exported types, unused
  shadcn parts and exports that exist for a test stay.

Nothing else is merged. Files run from about 20 to 500 lines, each doing one thing, and joining
them would trade a long list for long files.

## How it stays a move

- Every move is `git mv`, so history follows the file.
- Imports are rewritten by a script that resolves each one before the move and writes it again
  after: an `@/` import stays `@/`, a relative import stays relative inside one module and becomes
  `@/` when it crosses out.
- One commit per group (shared folders, directory and event-detail, entry, organiser), each with
  typecheck, lint and that group's tests green. No behaviour change rides along.
- At the end: the full `fe` suite, then the pages in a browser (`/`, a race, entering, `/org`,
  `/org/new`, a race console). `pnpm --filter fe build` is not run.
- `guides/ARCHITECTURE.md` (structure and layer rules) and the paths in `fe/CLAUDE.md` are updated.
