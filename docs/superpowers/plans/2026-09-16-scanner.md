# The volunteer's scanner — implementation plan (STE-22)

> **For agentic workers:** this plan is executed inline in the session that wrote it. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** a volunteer picks an event while they still have signal, downloads its roster, and then
works a check-in desk with none: a QR read by the camera or six characters typed by hand produce a
GREEN or RED verdict in under two seconds, computed entirely on the phone.

**Architecture:** a new feature module `fe/src/modules/scanner/` under the existing `(offline)`
route group, whose service worker already covers this kind of screen. The decision itself is one
pure function over three local inputs (the payload, the roster, this phone's queue). The check-in
code lives in `fe/src/lib/totp.ts`, moved up from the pass on its second user.

**Tech stack:** Next.js App Router, TanStack Query, idb-keyval, `BarcodeDetector` with a `jsQR`
fallback, vitest + Testing Library.

**Design:** `docs/superpowers/specs/2026-09-16-scanner-design.md`.
**Handoff:** `docs/design/race-day/README.md` (S1 to S11), `docs/specs/HASH_AND_TOTP.md` §4 to §5.

## Global constraints

- The code is a **six-character string**, never a number, everywhere (`HASH_AND_TOTP.md` §4.4).
- Tolerance is **±1 step of 30 s**, and it is read from the roster response rather than hardcoded.
- The QR payload is exactly `{"t":…,"s":…,"c":"…"}` and never carries the secret.
- The manual fallback takes **code + bib**, not code + token id.
- No full name anywhere: `name_fragment` is the most that reaches the screen.
- UI text is English, no em or en dashes, no technical jargon.
- Tests live in `__tests__/` beside the code they cover.
- A shared thing moves up in the same commit that adds its second user (`ARCHITECTURE.md` §4.2).

## Round 2: what happens to a claim afterwards

Planned in detail once round 1 is reviewed. The shape is fixed by the design §6: a queue screen (S9)
with the waiting rows, a sender (S10) that drains them one at a time through `claimRacepack` and
keeps the ledger each landed in, and the refused list (S11) at `/scan/[eventId]/flagged` for the
rows the chain answered `AlreadyClaimed(102)`.
